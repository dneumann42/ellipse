#+TITLE: The Owl REPL

* Goal

A repl you can write a whole program in, from nothing to files on disk, and
that doubles as a command line, a query tool over a codebase, and a live
editor for a running program. Everything above a few system primitives is
written in owl.

* Concepts

- Item :: a top-level piece of a module: a =fun=, =command=,
  =dynamic-command=, a binding (=x = ...=), =use=, =export=, or a statement.
  It has an exact line span, and the indent-0 comment directly above it
  belongs to it. Definitions and bindings are named; every item can be named
  by position, =#3=. See =libraries/source.owl=.
- Document :: the text of an owl module plus the live module it evaluates
  into. Every repl session has one active document. It starts unsaved and
  in memory, and can be written to a path. Other documents can be opened
  (any module of the project), but only one is active at a time.
- Patch :: an edit to a module's items that is both written to its text and
  applied to its live environment.

* Layers

| Layer       | What                                                  | Where                  | State   |
|-------------+-------------------------------------------------------+------------------------+---------|
| fs          | read-file, write-file (atomic), file-exists           | libraries/fs.nim       | done    |
| source      | items of a text, update/add/put/remove, exact spans   | libraries/source.owl   | done    |
| cli         | owl items/show/add/update/put/remove                  | scripts/cli.owl        | done    |
| imports     | =use= shares bindings through export views, no copies | objects.nim, modules   | done    |
| loader      | load modules from search paths; registry builtins     | modules.nim, loader.nim| done    |
| project     | project.owl, module name <-> file, =owl new=           | libraries/projects.owl | done    |
| live        | reload/patch/rerun/drop a loaded module, hooks        | libraries/live.owl     | done    |

* Source items (done)

Rules, enforced by =tests/source_test.nim=:

- =source-items= fails unless the whole text parses, so every span agrees
  with the evaluator.
- Updating any item with its own text, or with its code alone, gives the file
  back byte for byte (checked against every =.owl= file in the tree).
- =update-item= needs the same kind and name. When the new code has no
  leading comment, the old comment stays.
- =add-item= appends after the last non-blank line, one blank line apart, and
  refuses a name that already exists. =put-item= adds or updates by name.
- =remove-item= drops the item and its comment, plus one blank line when two
  would otherwise meet.
- New code must be nothing but items. A loose comment between items is
  refused rather than silently dropped.
- A name defined twice is ambiguous and must be given by position.
- Gap text (file header comments, blank lines between items) is never
  touched.

* Imports

=use m= attaches m's export table to the user's scope instead of copying
values. An export table maps each public name to the name of a binding in m's
own scope, so a name is looked up in m every time it is used:

- Re-making a definition in m reaches every module and scope that uses m,
  including through renamed exports (=export: shown = secret=).
- =set= on an imported name writes m's binding. There is one binding, not a
  copy.
- A scope's own bindings shadow its imports; among imports, the last =use=
  wins.
- An exported expression that is not a name (=export: x = (+ 1 2)=) is
  evaluated once, into a binding of its own.
- Exporting an unbound name is an error at load time.

Values captured in data (a lambda in a record, a closure held by a running
loop) still keep the code they captured. That's inherent, and it's what the
lifecycle hooks are for.

* Projects

A project is a directory holding =project.owl=, a file of plain bindings:

#+begin_src owl
name = "demo"
source = "src"   ; where modules live, relative to project.owl
main = "main"    ; the module `owl run` starts
#+end_src

Module names are paths under =source= without =.owl=: =use ui/button= is
=src/ui/button.owl=. =owl new <dir>= creates =project.owl= and
=src/main.owl=. The CLI, the repl and =owl run= find the project from the
current directory upwards.

** Projects from the repl

- =new-project <dir>= creates =project.owl= and =src/main.owl= in dir and
  switches to it. In the repl app, a bare =new-project= asks for the
  directory and whether it is a GUI app.
- =project= shows the current project. =open-project <dir>= switches to
  the project whose =project.owl= is in dir, or to a known project by name.
  In the repl app, a bare =open-project= picks from the known projects, the
  ones under the current directory, the current one's siblings, or a typed
  path.
- owl remembers the projects it has seen across runs, newest first, in
  =$XDG_DATA_HOME/owl/projects.owl= (=~/.local/share/owl/projects.owl=):
  =owl new=, =new-project=, opening a project and starting the repl in one
  add it. =projects= (or =owl projects=) lists them; one whose directory is
  gone is marked. =move-project <name> <dir>= points owl at its new
  directory, =forget-project <name>= drops it (its files stay).
- A switch closes the old project's documents. Unsaved ones are offered for
  saving (Save all / Discard / Stay); a served session refuses. It then
  unloads the old project's modules (each runs its =on-unload=), so a module
  name like =main= loads afresh from the new project. It swaps the search
  path and makes the new root the current directory, so relative paths read
  like after =cd=: =new-project ../other= makes a sibling.
- Documents with no file (=scratch=) stay open across switches. A scope that
  already used a module of the old project keeps its view of it.
- In the repl app the header names the project.

* Live modules

Every loaded module keeps the text it runs (=module-source=). =live.owl=
changes the text and the scope together.

- =reload-module name= re-reads the file and applies the difference:
  - Definitions are always re-made; the ones the text dropped are unbound.
  - A binding that is already bound keeps its value (state survives). A new
    one is evaluated; a dropped one is unbound. A kept binding whose code
    changed is reported, and =rerun-item= applies it.
  - =use= and =export= are redone from the new text.
  - A statement runs only if the old text did not have it.
- =patch-module name code= is what typing at the repl does. Each item is
  recorded in the text and evaluated, bindings and statements included. A
  named item replaces the one of that name, even of another kind; a =use=
  joins the other uses; anything else is appended. An item that fails to
  evaluate is not recorded.
- =rerun-item name key= evaluates one item again.
- =drop-item name key= removes an item from the text and unbinds it.
- Hooks: a module's own =on-load= fun runs after its first load, and its
  =on-reload summary= fun after each reload or patch. Being definitions, they
  are patched like anything else. =on-module name event fn= adds a hook from
  outside (events "reload" and "load").
  The summary record has =defined=, =bound=, =kept=, =removed= and =ran=.

* Printing values as code

=to-code value (width)= (Nim, next to =stringify= in =objects.nim=) writes a
value as owl source that evaluates back to it:
- On one line when it fits; otherwise as =[]:= / =\{\}:= blocks,
  =name = value= lines, and =concat:= over filled =[] ...= rows for long
  lists of atoms.
- Strings are quoted. A quote or control character becomes
  =(concat "a" (char 34) "b")=, since owl strings have no escapes.
- A list headed by a symbol is code and keeps its =:= body, so parsed code
  prints back as code. A fun prints as its definition.
=tests/evaluator_test.nim= checks the round trip at widths 20 to 200. The
repl prints every result this way; =stringify= (echo, concat) is unchanged.

* The repl

Each session starts a document named =scratch=, a module in memory whose
text starts with a small prelude of =use= lines. Code runs in the active
document's module and is recorded into its text. Inputs whose first word is a
command run in the repl and are never recorded; =x = 1= is code even when x
is a command name.

| Command                  | Does                                              |
|--------------------------+---------------------------------------------------|
| =docs=                   | list open documents, * is active, shows modified |
| =new [name]=             | start a new document                              |
| =open <module or file>=  | open a module as a document (loads it)            |
| =switch <name>=          | make an open document active                      |
| =save [file]=            | write the active document (default: its file, or  |
|                          | =<source>/<name>.owl= in a project)              |
| =text=                   | print the active document                         |
| =items [module]=         | list items                                        |
| =show <key> [module]=    | print one item                                    |
| =drop <key>=             | remove an item from the active document           |
| =rerun <key>=            | evaluate an item again                            |
| =reload [module]=        | re-read a module from its file, keeping state     |
| =modules=                | loaded modules and the project's modules          |
| =project=                | show the current project                          |
| =projects=               | list the projects owl knows                       |
| =open-project <dir>=     | switch to a project (a known one by name)         |
| =new-project <dir> [gui]= | create a project and switch to it                |
| =move-project <name> <dir>= | a known project moved to dir                   |
| =forget-project <name>=  | stop listing a known project                      |
| =run=                    | start the project's app and attach to it          |
| =apps=                   | list running owl programs                         |
| =attach <pid>=           | send input to a running program instead           |
| =detach=                 | leave it running and work here again              |
| =stop=                   | close the attached program                        |
| =settings=               | the repl's settings (a form)                      |
| =clear=                  | clear the transcript                              |
| =menu=, =help=, =exit=   | the command menu, the commands, leave             |

Each command is made with =interactive= in =repl.owl=, the way Emacs makes
a function a command:

#+begin_src owl
interactive show (item = read-item) module?:
    "print one item"
    show-item item (module-or-active module)
#+end_src

The head names the parameters, bound from the words typed after the
command: =x= must be given, =x?= may be left out. =(x = reader)= names the
fun that reads x on a screen when it is missing: always when it must be
given, from the menu only when it may be left out. The body opens with the
help text and may say =local= (runs in this repl even while attached) or
=screens= (runs here while attached, its screens reaching the program's
documents through =query=). The command joins the app's menu bar under
the menu the last =menu-section "Name"= named (=menu-section nothing=
keeps it off the bar). =help=, the F1 menu, the menu bar, reading what is
missing, logging the command it stood for and where it runs all come from
that one definition.

When a command fails it shows one line, never an error window. A
refusal (=refuse= in =repl.owl=) is a situation the line explains, with
what to do: "run needs a project: open-project, or new-project <dir> gui".
Anything else is a fault, and its line ends "details shows where":
=details= prints the whole report, the source with an arrow and the calls
that led there. Code typed into a document still shows its whole report,
since where it failed in your own code is the point.

A statement is recorded by what it changed, not as history (=run-statement=
in =live.owl=). The module's own bindings are compared before and after:
- Nothing changed (a query such as =tasks=, or =echo=): nothing is recorded.
- Bindings changed to data: each is written back as =name = value= in code,
  replacing its binding, so the document holds the state.
- A change that can't be written as code (a command or closure): the
  statement is recorded once; an identical one is never added again.

=items= shows a module's source in a scrollable view; ↑↓ select items and
PgUp/PgDn scroll. Enter or e edits an item: its text goes into the prompt,
and running it replaces the item. c copies it (the clipboard; OSC 52 in a
terminal), d drops it, r reruns it; the view's buttons do the same.
=results= (or F2) shows the printed results the same way, each under its
input as a =;= comment. Editing a result of a bare name the document binds
pre-fills =name = value=, so running it records that binding.

Opening another module and typing a definition patches the running module,
and since imports are live, every user of it sees the change.

* The repl app

=owl repl= is an ellipse_ui app written in owl (=scripts/repl-app.owl=):
it takes over the terminal, or opens a window when owl is built with SDL
(=make build_owl_sdl=) and there is a display. =owl repl --tui= keeps it
in the terminal. Without a terminal or a window it refuses to start.

The session (=scripts/repl.owl=) never draws. Where it needs an answer -- a
picked module, a typed name, a form, a confirmation -- it opens a /screen/,
a record of kind and title with a continuation (=done=), and the app draws
it and calls the continuation with the answer, or with nothing on Escape.
Everything the session shows is an entry of its transcript (input, printed
output, value, note, error); a served session prints them instead. The app
calls the session through =repl-*= functions, so it sees the live state;
=tests/repl_driver.owl= drives the same functions without the app.

| Area       | What                                                          |
|------------+---------------------------------------------------------------|
| menu bar   | a menu per section of the commands (F10 gives it the keys,    |
|            | Escape gives them back), then the project and unsaved docs    |
| transcript | inputs at their prompts, output, results as owl code; the     |
|            | wheel scrolls it, and it follows new lines                    |
| documents  | beside the transcript: a tab per open document (• unsaved)    |
|            | over the active one's items; a tab switches to its document.  |
|            | Alt+O gives it the keys: it is then the =items= view (same    |
|            | code), and Escape, C-g or a click on the prompt gives them    |
|            | back.                                                         |
|            | Attached, it shows the app's documents. Hidden below 80       |
|            | columns and while a screen is open                            |
| prompt     | where input goes (the active document, or the attached app),  |
|            | then a code editor (ellipse_ui's =editor=, monospaced)        |
| screens    | take the transcript's and documents' place until answered or  |
|            | cancelled                                                     |

Keys at the prompt:
- Enter adds a line, indented like the one above and one level deeper
  after a =:=; Ctrl+Enter runs the input (or Alt+Enter, Ctrl+J). The
  editor's own keys work: selection, undo, Emacs motions, the clipboard.
- Ctrl+Up / Ctrl+Down (or Alt+P / Alt+N, or Up on the first line and Down
  on the last) walk the history.
- F1 or Alt+X opens a filterable menu of every command; F2 the results;
  F3 shows or hides the documents.
- Ctrl+PgUp / Ctrl+PgDn switch to the previous / next document.
- Alt+O moves the keys to the document panel and back.

Keys in the =items= view and the focused document panel: Up/Down or
C-p/C-n move, PgUp/PgDn or M-v/C-v page, Home/End or M-</M-> go to the
ends; Enter or e edits (the item goes to the prompt), c copies, d drops,
r reruns; Escape or C-g closes.
- Ctrl+D on an empty prompt leaves; so do =exit=, Ctrl+Q and the window's
  close button, each asking first when documents are unsaved (Save all /
  Leave / Stay).

Screens:
- A command missing its argument opens a picker: modules for =open=,
  =items=, =reload=; documents for =switch=; the active document's items
  for =show=, =drop=, =rerun=; projects for =open-project=, known ones
  for =move-project= and =forget-project=. Typing filters (label
  matches rank first, then hints), ↑↓ move, Enter or a click picks. The
  equivalent typed command is shown, so the menu teaches the text form.
- =new= and =save= ask from the menu; =new-project= and =settings= are
  forms (Tab moves, Space toggles, Enter accepts).
- Keys typed in the same frame as Enter or Ctrl+Enter belong to what was
  being typed: a screen takes Escape and Enter before its fields see the
  frame's keys, and acts on them after.

=tests/repl_screens_test.py= drives the terminal app on a pseudo-terminal,
locally and attached; =tests/repl_gui_test.nim= drives the window app
headless with scripted keys and saves a screenshot of each screen to
=nimcache/repl_gui_*.bmp=.

The line editor and the terminal widget kit the repl used before
(=libraries/editor.owl=, =libraries/tui.owl=) are still in the library,
with =tests/tui_test.nim=; the repl no longer uses them.

* GUI projects

=owl new <dir> gui= (or =new-project <dir> gui= in the repl) makes a
project whose =project.owl= says =kind = "gui"=: =src/main.owl= opens a
window with =run-app= and uses =src/widgets.owl=. The app is built on
ellipse_ui itself (=libraries/gui.nim= is a bridge to it; ellipse knows
nothing of owl), and the owl half, =libraries/gui.owl=, adds:

- =widget [focusable] Name params...:= -- the port of ellipse_ui's
  =widget= macro, as a command that rewrites the definition into a =fun=
  whose body runs in an event frame shared with the Nim widgets. =emits
  Name field...=, =event Name e:= handlers, =emit Name (f = v)=, =reemit=
  and =handle-events:= behave as in =docs/ui.org=: bubbling through owl and
  Nim widgets alike, a handler consuming unless it reemits, =set e (with e
  ...)= changing what a reemit passes on, an emit in a handler starting at
  the parent frame. An undeclared emit is refused when the widget is
  defined. =widget-code Name= shows what a widget became. =widget= items
  are definitions to the live layer, so patching one replaces it.
- =run-app (title = ...): body= runs the frame loop and calls its body
  every frame. State is plain bindings (a reload keeps them); redefining
  =view= or a widget changes the next frame. A view that fails is shown
  over the window and retried each frame, so the fix brings it back.
- A parameter written =&name= (evaluator) takes the call's =:= block: a
  fun gets a closure over the caller's scope, a command the forms. Widgets
  use it for their block slot.
- =export all= makes a module public as it grows. Documents the repl
  makes in a project carry it, and a document saved into the project for
  the first time joins main's uses, so the app runs what the session
  builds.

* Runner and attach

A running owl app serves repls on a unix socket,
=$XDG_RUNTIME_DIR/owl/<pid>.sock= (mode 0600). The protocol and server are
owl (=wire.owl=, =attach.owl=): length-prefixed messages; =hello=, =input
<text>= (runs as typed at the app's own repl session, answers the active
document and the printed output) and =stop=. The app's session is its own
repl state (=serve-input= in =repl.owl=), not a terminal, with the main
module as the active document. Any number of repls may attach, one after
another or at once, and leave with =detach=; the session and its state
stay.

The app never waits on a repl. ellipse's frame loop sleeps in SDL's event
queue; =ellipse/platform/fdwatch= adds a helper thread that =poll()=s the
watched descriptors (the listening socket, each client, an inotify
descriptor) and pushes one SDL event when one is readable, so the request
runs on the main thread between frames and an idle app stays at 0 frames.
An input's answer is sent after the next frame, so it can say whether that
frame's view failed.

The app also watches its source directory (inotify) and reloads a module
whose file is saved, keeping state, so any editor works too.

While attached, the repl's screens still run in the repl: =items=
(the cursorable item view, with edit, copy, drop and rerun), =results=
(F2), =settings=, the F1 menu and every argument picker. They read and
change the app's documents through a =query= request, which evaluates owl
code in the app's session and returns the value as data along with what it
printed; locally the same code runs in this repl's session.
=tests/repl_screens_test.py= drives them, both ways.

=run= in the repl saves the project's documents, starts =owl run= in the
project root as its own process (output to
=$XDG_RUNTIME_DIR/owl/<name>.log=) and attaches. Editing happens in the
repl process, so the app's frame loop never slows the prompt down, and the
app keeps running after the repl leaves. =detach= reads back documents the
app saved. A terminal-only owl (the default build) has no windows, so the
app =run= starts runs unseen (attachable, reloading); to watch it, start it
with =owl run= in another terminal and =attach= to that one.

** Known gaps
- A reload that fails part way leaves the scope partly updated and the text
  unchanged. A dry run against a scratch scope first would make it atomic.
- =on-unload= runs only when a project switch unloads a module; there is
  no command to unload a single module.
- A directory created under =src/= while the app runs is not watched
  until it restarts.
- Attach and file watching are POSIX only (Linux tested); on Windows the
  net module and fd watching are stubs.
- Interpreter speed: symbol lookups hash strings, and command bodies are
  copied per call. Listing an 826-line module takes about 0.2s.
